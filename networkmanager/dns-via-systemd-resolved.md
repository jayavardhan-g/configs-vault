# NetworkManager hands DNS to systemd-resolved (fixes Tailscale's MagicDNS warning)

**Date:** 2026-11-07
**Category:** networkmanager
**Files touched:** `/etc/NetworkManager/conf.d/dns.conf` (copy: [`files/etc/NetworkManager/conf.d/dns.conf`](files/etc/NetworkManager/conf.d/dns.conf)), `/etc/resolv.conf` (now a symlink, not a file)

<!-- graph:begin -->
**Graph:** [[Tailscale]] · [[Home server]] · [[NetworkManager]]
<!-- graph:end -->

## What
On the laptop, NetworkManager now passes DNS to systemd-resolved instead of writing
`/etc/resolv.conf` itself, and `/etc/resolv.conf` is the standard symlink to resolved's stub.
The home server got the same fix at setup (Phase 4 in [[homeserver-setup]]).

## Why
Tailscale reported "systemd-resolved and NetworkManager are wired together incorrectly;
MagicDNS will probably not work". `/etc/resolv.conf` was a regular file "Generated by
NetworkManager" (pointing at `127.0.0.53`, so DNS itself worked), with resolved running in
"foreign" mode. Tailscale wants resolved to own the file so it can add the tailnet's names
(`*.<tailnet>.ts.net`) cleanly.

## Change
```ini
# /etc/NetworkManager/conf.d/dns.conf
[main]
dns=systemd-resolved
```
```bash
sudo cp /etc/resolv.conf /etc/resolv.conf.bak.$(date +%s)
sudo ln -sf /run/systemd/resolve/stub-resolv.conf /etc/resolv.conf
sudo systemctl restart systemd-resolved NetworkManager
sudo systemctl restart tailscaled
```

## Verify
Checked 2026-11-07, with WARP both off and on: `getent hosts archlinux.org` and
`getent hosts <nas>.<tailnet>.ts.net` both resolve; `tailscale status --json` → `Health`
empty; `ls -l /etc/resolv.conf` → `-> /run/systemd/resolve/stub-resolv.conf`.

## Notes
- Applied with a one-off script that tested DNS (normal and tailnet names, WARP off and
  on) and would have restored the backup and removed `dns.conf` if any test failed. It
  passed, so nothing was rolled back. Backup: `/etc/resolv.conf.bak.<epoch>`.
- WARP on the laptop runs in full `warp` mode (it handles DNS too); it worked fine with
  this change in both states.
- To undo: `sudo rm /etc/NetworkManager/conf.d/dns.conf`, restore the backup over
  `/etc/resolv.conf`, restart `systemd-resolved`, `NetworkManager`, `tailscaled`.
